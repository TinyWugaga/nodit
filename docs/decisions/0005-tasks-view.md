# 0005 — Tasks view：追蹤任務執行狀態

- 狀態：Proposed
- 日期：2026-10-22（同日修訂：統計改為只算已存檔的值）
- 延伸：0003 的資料來源與寫入協定

## 背景

Graph Canvas 適合看關係：Task 實作哪個 ADR、隸屬哪個 Milestone、依賴誰。它不適合追進度：哪些卡住、誰手上有幾張、某個 Milestone 還差多少。這些在圖上都要逐張找。

現有的 Task 欄位（`status`、`priority`、`assignee`、`milestone`、`depends`）和寫入 API 已經足以支援追進度，不需要另建任務系統。

## 決策

新增第三個 view「Tasks」，與 Graph Canvas、Architecture 並列。同一份任務資料，Graph 看關係，Tasks 看執行狀態。不新增 server API，`docs/` 的 markdown 仍是唯一真相。

### 看板與分組

- 欄位固定是 Task 的四個 status：`todo`、`doing`、`blocked`、`done`。
- 預設不分組。可切換成單一分組：milestone、assignee 或 priority。一次只能選一種。
  - 沒有對應值的卡片歸到「未指定」組。
  - milestone 分組依 `links.milestone` 的 ID 對應；對應不到卡片時，以原始 ID 成組，並標示無法解析。
- 欄內排序固定：priority（high → low），再依 ID。不保存手動順序。
  - 手動順序其實可以存成瀏覽器偏好，不必改 0003 的格式；代價是不跨裝置、不共享。目前沒有需要，所以不做。

### 拖曳只改 status

- 拖到另一欄，只修改 `status`。
- 分組時只能在同一組內跨欄拖曳。跨組拖曳一律禁用，避免使用者以為拖動會同時改 assignee、milestone 或 priority。這些欄位照舊在 Inspector 修改。
- 不可寫入的卡片（legacy、無效、唯讀）不能拖曳。
- 拖曳是一次性修改，沿用 Inspector 下拉選單的寫法：寫入草稿後立刻 `flush`。

### 寫入沿用草稿流程，狀態顯示在卡片上

- `DraftManager.flush()` 會送出該文件所有 pending 欄位，不是只送 status。拖曳一張還有未送出修改（例如標題正在 debounce）的卡片，會把那些修改一起儲存。**明確接受這個行為**：它跟 Inspector 裡改下拉選單的結果相同，草稿本來就是以文件為單位。
- 卡片移欄後立刻以草稿值顯示在新欄位，並在卡片上直接顯示同步狀態，不能只在 Inspector 裡提示：
  - 未儲存、儲存中、衝突、無效、失敗、無法寫入（token／session 失效）。
  - 磁碟版本在草稿期間被更新時，另外標示。
- 保留草稿的既有語意：
  - 衝突或無法寫入的草稿不會自動重送。卡片停在草稿值的欄位，並標示狀態；要重試、捨棄或重新套用，都到 Inspector 處理。
  - 不在寫入成功前把卡片顯示成「已儲存」。

### 統計的定義

統計一律以全部 Task 計算。搜尋只縮小卡片清單，不影響任何統計數字，UI 上要標明這一點，避免搜尋後完成率突然變成 100%。

統計只算已存檔的值（磁碟上的 `status` 與 `assignee`），不算草稿。卡片仍照草稿值放在欄位裡。

- 原因：寫入中、衝突或失敗的草稿不代表檔案已經改變。把它算進統計，失敗的拖曳也會讓完成數或負荷看起來已經變了。
- 代價：草稿存檔前，欄位標題的卡片數可能和統計對不上。有未存檔修改時，UI 要標明「n 個任務有未存檔的修改，不計入統計」。
- 卡片放在哪一組仍依草稿值；統計歸屬（例如 assignee 負荷）依已存檔的值。Milestone 歸屬本來就以磁碟上的連結為準。

- **Milestone**：顯示「已完成任務數 / 總任務數」，用的是任務數量，不暗示工作量完成率。沒有任何任務時顯示「尚無任務」，不顯示 0/0 或 0%。
  - 任務屬於哪個 milestone，以該 Task 的 `links.milestone` 為準。
- **Assignee**：`doing` 與 `blocked` 分開計數。合併計數會讓卡住的工作從負荷統計裡消失。
- **Priority**：只顯示各組的卡片數。

### 依賴提示

- 只檢查直接 `depends`，不追遞移依賴。
- 分成兩種提示，不能混為一談：
  - **依賴未完成**：對應到唯一一張 Task，而且它的 status 不是 `done`。
  - **依賴無法解析**：找不到這個 ID，或有多張卡片使用同一個 ID。無法解析不能當成「未完成」，因為 Nodit 無法判斷它的實際狀態。
- 不自動把 status 改成 `blocked`。`blocked` 也可能是在等外部回覆，與依賴狀態不能畫上等號；自動改狀態也等於 Nodit 自己寫檔，會和 AI 或手動編輯互相干擾。

### 不做

留言、工時、sprint、通知。

## 後果

- 使用者不必在圖上逐張找卡片，就能看出進度、卡住的工作和每個人的負荷。
- 拖曳可能順帶存下同一份文件尚未送出的其他欄位；這是草稿以文件為單位的直接結果。
- view 狀態新增 `tasks`。Sidebar 點擊卡片的行為不變：非 Graph view 時跳回 Graph 並聚焦該卡。
